Make discovery in the existing `kogen init` flow use the user's supported authenticated provider/executor, not an unconditional ChatGPT login and default Shape request. This belongs entirely in kogen-setup, which received init from kogen-shaping on 3 Nov. Preserve the exported Init/InitInput interface and the agreed CLI: no new or changed commands or flags. Do not change provider protocols or executor contracts. Reuse the pinned provider and Claude Code adapter capabilities. Do not acquire accounts or bootstrap fresh Claude tokens; coordinate that prerequisite as a managed-runtime follow-up. Tests use only synthetic local credentials, fake providers and fake managed runtimes; no real-account qualification or paid initialization is authorized.

## Decisions
- Existing valid configuration wins over every login, including explicit native bindings and mixed providers/executors. Already committed configuration remains byte-identical with no request or commit; valid leftover configuration retains the existing commit-as-is behavior. Login is authentication, not permission to overwrite roles. (source: request)
- For a new project with one usable route, select it unambiguously and report the selection; with multiple usable routes show a numbered interactive chooser inside init. Without a terminal stop with a selection-required error before any model request or configuration write/commit. Number supported native provider candidates in catalog order, then Claude Code; thus ChatGPT and Claude Code alone are choices 1 and 2. Blank/invalid choice or EOF must not select a default route or change billing. (source: answer 1)
- Missing authentication stops honestly with existing provider-login guidance; no ChatGPT-only requirement, manual YAML workaround, or paid fallback. An authenticated route that subsequently rejects authentication or fails remains an honest error on that route, never automatic failover. (source: request)
- The new-project selection applies to discovery and the initial shape/build/review roles, so the result is usable without hand-authoring configuration. Display this scope when offering the choice. Preserve ChatGPT's existing model/effort defaults. For native non-ChatGPT routes use the first catalog model and high effort for shape/review, medium for build (OpenCode Go uses high for shape/review and default for build). For Claude Code use claude-sonnet-5-5, high for shape/review and medium for build, executor claude-code, with existing round defaults. Persist explicit native provider selection; do not change previously configured roles. (source: request)
- OpenAI-compatible routing requires an actual host/base URL and model, not merely an optional saved key. Never invent those or select a public paid endpoint. Existing valid compatible role configuration is preserved. A saved key without an unambiguous model/host is not an automatic discovery candidate; explain the missing route information honestly. This item changes selection of already supported complete routes, not compatible-host onboarding or new CLI configuration interfaces. (source: request)
- Preserve actual setup/check/acceptance discovery, validation and retries, command verification on a committed-tree copy, coverage/left-out review, Cucumber bridge behavior, protection filtering, repository preconditions, cancellation/errors, exact committed paths, commit subject and one-commit behavior. No scaffolding, project cleanup or test-framework replacement. Update local onboarding copy to remove an unconditional ChatGPT prerequisite while retaining the review-of-omissions step. (source: request)
