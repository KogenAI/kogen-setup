# Refuse commands longer than 2000 characters

Slug: k-setup-command-length-bounded
Model: not applicable — stateless validation of one proposal's setup, fix and check commands and the wording of one refusal
Acceptance:
- .kogen/intents/k-setup-command-length-bounded/acceptance.feature
- features/steps/k-setup-command-length-bounded__validate.js

In setup/init.go, `Validate` limits how many setup, fix, check and protect entries a proposal has (`initMaxSetup`, `initMaxFix`, `initMaxChecks`, `initMaxProtect`) and how long a check name is (`initCheckNameMax`), but not how long one command is. Observed on the unchanged tree: setup, fix and check commands of 2001 `x` characters are all accepted into the proposal with no problem, and a 2001-character check that names the project folder by absolute path gets the existing absolute-path refusal with the whole command echoed (a problem of about 2077 characters).

After the change, `Validate` refuses a setup, fix or check command longer than 2000 characters (a new fixed bound next to the other `initMax*` constants) with exactly
`<kind> command <first 40 characters>… is longer than 2000 characters; put long scripts in a file in the project and run that`
where `<kind>` is `setup`, `fix` or `check <name>` (the check's name, e.g. `check lint command …`), and `…` is the single character U+2026 directly after the 40 characters, with no space. Example: a setup command of 2001 `x` gives `setup command xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx… is longer than 2000 characters; put long scripts in a file in the project and run that`. Characters are Unicode code points (Go runes), as for the check-name bound: the length is the command's rune count, and the shown prefix is its first 40 runes, never a split UTF-8 sequence. The prefix is taken from the command after credential redaction (the redacted text `initCredentialLiteral` returns; unchanged when the command has no credential literal), so the length refusal never shows a secret the credential refusal would have hidden. When those 40 characters contain a control character (`unicode.IsControl`), they are shown as Go's `strconv.Quote` of the 40 characters followed by `…`, as the check-name length refusal does, so a newline never enters a problem raw.

An over-long command gets the length refusal once and no other refusal that is about that command: no shell-syntax refusal, no credential-literal refusal, no control-character refusal, and none of the per-command refusals (machine prerequisite, runs nothing, ignores its own failure, runs tests or linting, installs dependencies, names the project folder by absolute path, reaches outside the project folder, changes the repository state, does not exit on its own, publishes or deploys, references an unset variable). Refusals that do not echo the command keep applying as today: the entry-count limits, `<key> must be a list`, `<key> must be a list of non-empty commands`, and the check-entry refusals of `initChecks` (missing name/run, reserved, too-long or invalid name, used twice, no command). The length refusal of a setup or fix command is reported where Validate reports that command's other problems today (the setup and fix loops over the commands `initStrings` returned); for checks it is reported for each check `initChecks` accepted (so a check whose name is refused gets its name refusal, and its over-long command is not echoed anywhere). The problems therefore keep today's order: check problems before setup problems before fix problems. As today, Validate returns its empty proposal whenever there are problems.

Nothing else changes: commands of 2000 characters or fewer follow exactly today's rules and wording, and a valid proposal is returned, and written to `.kogen/project.yaml`, exactly as today. No prompt, tool definition, golden file or configuration format changes. The progress lines, `Left out:` entries and `Setup:` summary are not changed directly; they stop carrying over-long commands because such commands no longer pass validation.

## Decisions
- A setup, fix or check command longer than 2000 characters is refused with `<kind> command <first 40 characters>… is longer than 2000 characters; put long scripts in a file in the project and run that`, `<kind>` being `setup`, `fix` or `check <name>`; commands of 2000 characters or fewer are not affected. (source: request)
- An over-long command that also breaks another rule gets only the length refusal, once; refusals that never echo the command (count limits, list shape, check-name refusals) still apply. (source: request)
- Characters are Unicode code points (Go runes) for both the 2000 bound and the 40-character prefix, and `…` is U+2026 directly after the prefix, matching the check-name length refusal. (source: request)
- The refusal must be short and must not echo what other refusals hide: the prefix comes from the credential-redacted command, and is shown with `strconv.Quote` when it contains a control character. (source: request)
- Problems keep today's order (checks, then setup, then fix). (source: request)
