# Strip control characters from init output tails

Slug: k-setup-output-tail-control-sequences
Model: not applicable — a per-line text transformation of captured command output; no state or interacting rules
Acceptance:
- .kogen/intents/k-setup-output-tail-control-sequences/acceptance.feature
- features/steps/k-setup-output-tail-control-sequences__init.js

When `kogen init` leaves out a setup, fix or check command, `initShowOutput` in `setup/init.go` writes the last lines of that command's captured output to stderr as progress lines, formatted by `initOutputTail`. Today `initOutputTail` only splits the output into lines, keeps the last 20, cuts each to 200 runes and prefixes `  | `; control characters pass through unchanged. A failing tool that prints colour codes, a carriage-return progress bar, a terminal title sequence or a bell makes the diagnostic unreadable, can overwrite the `  | ` marker so the line looks like a Kogen status line, and can alter the user's terminal. Observed on the unchanged tree for the check `bad` below: stderr holds `  | \x1b[31mred boom\x1b[0m`, `  | one\rtwo` and `  | a\x07b` as raw bytes.

The product should remove control characters from each output line before it is cut to width. `initOutputTail(output string) []string` keeps its signature, and `initShowOutput` keeps writing each returned line with `s.Progress`. Splitting on `\n` after trimming one final `\n`, the empty-output result (nil) and the selection of the last 20 lines stay exactly as today (lines are counted before cleaning, and a line that becomes empty still prints `  | `). Each selected line is then cleaned in this order:

1. ANSI escape sequences are dropped whole. A CSI sequence is ESC (U+001B) followed by `[`, up to and including the first character in U+0040–U+007E. An OSC sequence is ESC followed by `]`, up to and including the first BEL (U+0007) or ESC `\` (string terminator). A sequence whose terminator does not occur in the line is dropped to the end of the line.
2. Carriage returns at the end of the line are removed; then, if the line still contains a carriage return, only the text after the last one is kept. So `one\rtwo` shows `  | two`, `FAIL foo\r` (Windows-style CRLF output) shows `  | FAIL foo`, `10%\r20%\r` shows `  | 20%`, and a line that is only `\r` shows `  | `.
3. Every remaining control character except tab (U+0009) is removed: the runes for which Go's `unicode.IsControl` is true, that is U+0000–U+001F, U+007F (DEL) and U+0080–U+009F. An ESC that does not start a CSI or OSC sequence is removed alone and the characters after it are kept (`\x1b(Bx` shows `  | (Bx`). Tabs are kept as they are.
4. The cleaned line is cut to its first 200 runes and prefixed with `  | `, as today. Because cleaning comes first, an escape-coloured line of 200 visible characters shows all 200.

Invalid UTF-8 keeps today's handling (each invalid byte becomes U+FFFD through rune decoding). Output with no control characters other than tab renders exactly as today.

Boundaries: the `  | ` prefix, the 20-line and 200-character bounds, which commands are kept or left out, the progress lines `kogen: checking <name>: <command>` and the other stderr lines, stdout (including the `Left out:` entries, which show the command text unchanged), the committed `.kogen/project.yaml` and `.kogen/models.yaml`, the prompt and tool definitions and exit codes do not change. No setting or option is added.

The acceptance step builds the `setup` test binary from a copy of the checkout with one extra driver test it writes itself (`TestOutputTailControlSequencesIntentCapture`), which uses the existing `setup` test fixture helpers `initNewFx`, `initSubmit`, `initScrub` and the `initFx` methods `write`, `commitAll`, `run` and `git`, and `project.LoadConfig`/`project.ConfigPath` from `github.com/KogenAI/kogen-coordinator/project`; keep those helpers and their signatures.

## Decisions
- Each output line written by `initShowOutput` has control characters removed before it is cut to width: CSI and OSC escape sequences are dropped whole, a carriage return keeps only the text after the last one, and any other control character except tab becomes nothing. (source: request)
- The `  | ` prefix, the 20-line and 200-character bounds, stdout, the committed configuration and exit codes do not change; output with no control characters renders exactly as today. (source: request)
- Carriage returns at the end of a line are ignored before the last-carriage-return rule applies: `FAIL foo\r` shows `  | FAIL foo`, `10%\r20%\r` shows `  | 20%`, `one\rtwo` still shows `  | two`. (source: answer 1)
