# Qualify init checks in a Git copy

Slug: setup-init-qualifies-git-reading-checks
Model: not applicable — this changes how the scratch copy that init verifies commands in is prepared, not workflow state or transitions
Acceptance:

- features/steps/setup-init-qualifies-git-reading-checks__init.js

`kogen init` runs every discovered setup, fix and check command in a scratch copy of the committed tree. That copy has no `.git` directory (and no `.kogen/local`), so a command that needs the repository (`git ls-files`, `git rev-parse`, `git diff`) fails there for a reason that has nothing to do with the project; init then drops the check, writes `commands.checks: []` in `.kogen/project.yaml` and still reports success. After this change the copy is a real Git work tree whose HEAD tree equals the committed tree (HEAD) of the real repository, so a command that works in the repository also qualifies, and a command that genuinely fails is still refused.

The copy's repository is created inside the scratch copy only: a fresh `git init`, a fixed throwaway identity (`Kogen Init <init@kogen.invalid>`), `commit.gpgsign` false, `core.hooksPath` set to `/dev/null`, no remote, with HEAD fetched by path from the real repository (a read-only fetch, no remote configured) and the index reset to it. It is never a link to the real repository's `.git`, so a command cannot touch the user's repository, refs, index or hooks. The Git location variables (the set `git.UnsetPrefix` already unsets) are unset for the init commands run in the copy, as they already are for the other Git runs. Uncommitted edits and untracked files of the real working tree are not part of the copy's HEAD or working files, as today. Commands that contact remote hosts remain refused by the existing rule.

Nothing else changes: which commands are proposed, the verification report format, the exit codes, the refusal of a check that fails in the committed copy, the real repository, its index and its working tree (unchanged by init except for init's one configuration commit, as today).

Acceptance runs the compiled standalone `cmd/kogen-setup` command on a fixture repository with a local scripted proposal and no network or live provider; it reads the exact summary lines and the real repository's history, local configuration, hooks and working tree. It does not depend on any test the Build writes. The Build also adds the focused, model-free Go tests of the Tests section in `setup/init_git_copy_test.go`, using the existing helpers of `setup/init_test.go` (`initNewFx`, `initSubmit`, `initCheckList`, the fake route); each runs alone with `go test ./setup -run <its name>`.

## Decisions
- The copy becomes a Git work tree by `git init` inside the copy followed by a path fetch of the real repository's HEAD and a mixed reset to it, done at the end of `initCommittedCopy` in setup/init.go, after the changed files are restored (today by `git archive HEAD` piped to tar). This keeps the HEAD tree exactly the committed tree even for tracked files that the ignore rules would hide from a commit of the copy, and creates no remote. (constraint: never a symlink or GIT_DIR link to the real .git; throwaway identity, no remote, hooks disabled) (evidence: setup/init.go) (source: request)
- The Git location variables are also unset for every verification command init runs in the copy (`initExec`), so a GIT_DIR inherited from the caller cannot redirect a command to the real repository. (constraint: uses git.UnsetPrefix) (evidence: setup/init.go) (source: request)
- The copy's own `.git` directory is skipped when init records the empty directories to retain after a check run. (evidence: setup/init.go) (assumption: Init's tree-state, clean and snapshot logic keeps observing the copy with the real repository's git dir and the copy as work tree, which ignores a root `.git`; only the directory walk needs the skip.) (source: request)
- Acceptance observes the behavior through the compiled standalone init command and the real repository, not through the named Go tests, which the Build adds separately.
