# Bound left-out path lists in init output

Slug: setup-init-left-out-path-lists-state-the-count
Model: not applicable — this changes how a list of paths is rendered in one summary line, not workflow state or transitions
Acceptance:
- .kogen/intents/setup-init-left-out-path-lists-state-the-count/acceptance.feature
- features/steps/setup-init-left-out-path-lists-state-the-count__init.js
- features/steps/setup-init-left-out-path-lists-state-the-count__driver/init_path_list_test.go.txt

The `Left out:` summary line of `kogen init` names the files a command changed in two inconsistent ways. A check or setup command that changed more than five tracked files is shown with the first five and a trailing comma and three dots, so the user cannot tell whether one or five hundred more were changed. Every other list of changed paths in the same summary (a setup command whose second run changed files, a fixer whose second run changed files, a fixer that changed protected files) is joined in full, so a command that touches thousands of files produces a single summary line of thousands of paths. After this change every one of these lists shows at most five paths and then says how many more there are.

One helper, `initPathList(paths []string) string` in setup/init.go, replaces `initChangedDisplay` (removed completely, no alias) and every `strings.Join` of a changed-path list in the left-out entries: the setup `is not repeatable: its second run changed` entry, the setup `changed` entry, the check `changed` entry, the fixer `changed protected` entry and the fixer `is not repeatable: its second run changed` entry. For five paths or fewer the result is the paths joined with a comma and a space, exactly as before. For more it is the first five joined the same way, then ` and ` + the number left over (the count of paths beyond the five shown) + ` more`: `f1.txt, f2.txt, f3.txt, f4.txt, f5.txt and 2 more`, and for one left over `and 1 more`. The input order is kept (`initStateDiff` and `initTrackedChanged` already return sorted paths). Wrong forms are `and 1 more paths` and counting the five shown (`and 6 more` for six paths).

The text around the list in each entry is unchanged, for example `fix-1 (printf x >> f.txt) is not repeatable: its second run changed f.txt`; only the list changes. Unchanged: which commands are kept or left out, the reasons, the order of entries, the paths detected as changed, the restoring of the copy, the written configuration, the commit and exit codes. Lists of five paths or fewer print exactly as before. Left-out entries that name no path list are untouched. No flag, setting or environment variable. No change to kogen-verification, kogen-loop or the kogen CLI.

Acceptance observes the behavior through the compiled standalone `cmd/kogen-setup` command on a fixture repository with a local scripted proposal and no network or live provider; it reads the exact `Left out:` line of the summary, so it does not depend on any test the Build writes. The Build also adds the focused, model-free Go tests in `setup/init_path_list_test.go` next to init_fix_repeat_test.go, with the content of the reference copy `features/steps/setup-init-left-out-path-lists-state-the-count__driver/init_path_list_test.go.txt` (a protected file that is not itself compiled).

## Decisions
- Replace `initChangedDisplay` and the five full-join sites with a single `initPathList` helper in setup/init.go; no alias is kept. (decision: D1, round 1) (constraint: the helper is named initPathList and takes and returns exactly []string and string) (evidence: setup/init.go) (source: request)
- The bound is the constant five paths; the remainder text is ` and N more` where N is the count of paths beyond the five shown, with no pluralization variant. (decision: D2, round 1) (constraint: no flag, setting or environment variable) (evidence: setup/init.go) (source: request)
- Acceptance runs the compiled standalone init command against a local scripted proposal and compares the exact `Left out:` line, so the helper is observed through its five call sites and the six-path remainder count rather than through a named test. (decision: D3, round 1) (constraint: each scenario has its own fixture repository and finishes within the 120 s step limit) (evidence: cmd/kogen-setup/main.go; setup/init_fix_repeat_test.go; setup/init_fix_protect_test.go) (assumption: The request asks for Go tests in setup/init_path_list_test.go and says nothing about acceptance through the compiled kogen-setup command, or about replacing the unit scenario with a call-site observation.) (source: request)
