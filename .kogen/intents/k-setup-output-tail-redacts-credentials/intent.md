# Redact credentials in init output tails

Slug: k-setup-output-tail-redacts-credentials
Model: not applicable — a per-line text transformation of captured command output; no state or interacting rules
Acceptance:
- .kogen/intents/k-setup-output-tail-redacts-credentials/acceptance.feature
- features/steps/k-setup-output-tail-redacts-credentials__init.js

When `kogen init` leaves out a setup, fix or check command, `initShowOutput` in `setup/init.go` writes the last lines of that command's captured output to stderr as progress lines, formatted by `initOutputTail`. Init already refuses a proposed command containing a credential literal and shows it redacted, using `initCredentialLiteral(command string) (string, bool)` in `setup/init_credentials.go`, which replaces each detected secret value with `***`. But the output tail is printed without that detection: a failing tool that echoes `API_TOKEN=...`, an `Authorization: Bearer ...` header or a URL with a password puts the secret on the user's terminal and in any log of init's stderr. Observed on the unchanged tree for check `bad` below: stderr holds `  | API_TOKEN=abcd1234secretvalue`.

The product should pass every output line through the same credential detection before it is shown. `initOutputTail(output string) []string` keeps its signature, and `initShowOutput` keeps writing each returned line with `s.Progress`. Splitting on `\n` after trimming one final `\n`, the empty-output result (nil), the selection of the last 20 lines (counted before cleaning) and the control-character cleaning of each line (`initCleanOutputLine`) stay exactly as today. Each selected line is then, in this order:

1. cleaned of control characters, as today;
2. passed as a string to `initCredentialLiteral`; when it reports a credential, its returned text (each secret value replaced by `***`, the rest of the line as it was) replaces the line, otherwise the line is unchanged. No new detection rule, pattern or marker is added; whatever `initCredentialLiteral` detects in a command it detects in an output line;
3. cut to its first 200 runes and prefixed with `  | `, as today. Redaction comes before the cut so that the cut cannot split a secret out of detection: a line of 180 `0` characters, a space and `https://bot:abcdefghijklmnop@git.invalid/x.git` shows `  | ` + 180 zeros + ` https://bot:***@git` (200 runes), where cutting first would show the unredacted `https://bot:abcdefg`.

Lines in which `initCredentialLiteral` finds no credential render exactly as today.

Boundaries: the `  | ` prefix, the 20-line and 200-character bounds, the control-character cleaning, which commands are kept or left out, the progress lines `kogen: checking <name>: <command>` and the other stderr lines, stdout (including the `Left out:` entries, which show the command text unchanged), the committed `.kogen/project.yaml` and `.kogen/models.yaml`, the command validation messages, the prompt and tool definitions and exit codes do not change. No setting or option is added.

The acceptance step builds the `setup` test binary from a copy of the checkout with one extra driver test it writes itself (`TestOutputTailRedactsCredentialsIntentCapture`), which uses the existing `setup` test fixture helpers `initNewFx`, `initSubmit`, `initScrub` and the `initFx` methods `write`, `commitAll`, `run` and `git`, and `project.LoadConfig`/`project.ConfigPath` from `github.com/KogenAI/kogen-coordinator/project`; keep those helpers and their signatures.

## Decisions
- Each output line written by `initShowOutput` is passed through `initCredentialLiteral`, the credential detection init already uses for commands, and a detected secret value is replaced by the same marker `***` before the line is shown. (source: request)
- Lines with no credential render exactly as today; the 20-line and 200-character bounds, the `  | ` prefix, stdout, the configuration and exit codes do not change. (source: request)
